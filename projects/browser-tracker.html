A local activity picture, built only from the visitor's own browser.

Browser Tracker is the display name used on the site. The extension manifest names it Browser Usage Tracker and records version 0.2.0. It is a Chromium-based Manifest V3 extension paired with a page-side dashboard bridge.

The extension estimates active time in the foreground, counts open tabs, and stores per-domain totals on the device. A visitor can opt into sharing aggregated totals with a local dashboard or allowed localhost page. Nothing is sent to a server, and no account is created.

PURPOSE

See your own browsing time

Provide a private, local view of active time, open tabs, and most-used domains without an analytics service.

SCOPE

Estimates, not telemetry

Active time is inferred from focus, tab, window, and idle events. It is not exact runtime and does not track other applications.

This status is based on source inspection in this repository. The extension was not installed or exercised in a browser as part of this deep dive.

02 / PROBLEM & USERS

A dashboard should show real data without collecting someone's history.

The documented problem is a familiar one for browser utilities: people want a useful activity summary, but a conventional analytics path would require a server, an account, and far more access than the summary needs. The extension keeps aggregation on the device and lets the visitor decide whether any totals leave it.

Intended users and use cases

  • A site visitor who installs their own unpacked extension and wants to see personal active-time totals on the portfolio dashboard.
  • A developer reviewing a privacy-sensitive pattern for local aggregation, explicit consent, and labelled empty states.
  • A portfolio reader comparing an implemented local tool with concepts that have no source code in this repository.

These uses are taken from the repository's own README, homepage copy, and handoff notes. No user research, customer list, or adoption claim is documented.

04 / ARCHITECTURE

Four local stages, one consent-gated bridge.

IMPLEMENTED / SERVICE WORKER

Browser events

The service worker listens to focus, tab, window, idle, alarm, startup, and install events. It estimates active time only for a focused normal window and its active tab.

Extension structure

  • manifest.json declares the MV3 service worker, popup, options page, fixed public key, four permissions, and external connection allowlist.
  • background/service-worker.js owns the tracking state machine, settings, snapshot generation, pruning, and message handling.
  • shared/aggregate.js normalises domains, formats day keys, splits midnight intervals, and prunes retention windows.
  • popup/ and options/ provide the visitor-facing controls.
  • js/browser-tracker.js is the page-side bridge that polls the extension and renders the dashboard.
  • js/tracker-tutorial.js runs the four-step onboarding modal.

05 / FEATURES

Verified controls and interactions.

POPUP

Local status at a glance

Status pill, today's HH:MM:SS total, open tabs, most-used domain, ranked site bars, sharing toggle, Pause, Clear, and an options link.

OPTIONS

Explicit boundaries

Pause, sharing, Incognito opt-in, idle threshold from 15–300 seconds, retention from 7–365 days, and excluded domains.

DASHBOARD

Consent-gated live view

Polls for a ping, then requests a snapshot once sharing is on. Shows active time, open tabs, top domains, a seven-day history, and Pause/Clear controls.

EMPTY STATE

Honest disconnected view

Install steps, a Chromium-only note, and an explicitly labelled illustration with no fabricated visitor statistics.

Technologies actually used

JavaScript ES modules, Manifest V3, chrome.storage.local, chrome.storage.session, chrome.alarms, chrome.idle, chrome.tabs, chrome.windows, and chrome.runtime messaging. HTML and CSS build the popup, options page, dashboard, and onboarding modal. The site build uses esbuild, but the extension is not copied or bundled by that build.

Permissions and connections

The manifest requests exactly four permissions: storage, alarms, idle, and tabs. It declares no host_permissions. externally_connectable lists HTTPS GitHub Pages plus http://localhost/* and http://127.0.0.1/*; the service worker validates the sender URL and path before responding.

06 / PRIVACY

The data path stays on the device until sharing is enabled.

  • Totals live in chrome.storage.local; the in-progress interval lives in chrome.storage.session.
  • Aggregates contain active time, domain keys, activation counts, and tab counts. Snapshots add generated time, status, top domains, and seven-day history.
  • The source explicitly excludes full URLs, paths, query strings, fragments, page titles, form contents, passwords, raw history, tab IDs, and window IDs from the shared object.
  • No fetch, XHR, beacon, storage.sync, content script, or remote code was found in the extension.
  • Sharing defaults to off. Pause, Clear, excluded domains, Incognito opt-in, idle threshold, and retention are visitor-controlled.

Security posture is defined by the code path, not by a formal audit. No penetration test, threat model, or independent privacy review was found in this repository.

08 / LIMITATIONS

What the implementation deliberately does not cover.

  • Installation is unpacked and requires Developer mode in a Chromium-based browser; it is not listed in an extension store.
  • Active time is an estimate from focus, tab, window, and idle events. Background tabs, other applications, time with the browser closed, and data from before installation are excluded.
  • Incognito is counted only when the visitor enables it and the browser setting permits it.
  • Domain normalisation uses a small built-in public-suffix list, so unusual suffixes may group imperfectly.
  • No system metrics such as RAM, CPU, GPU, temperature, or process time are collected.
  • The Python desktop interface is documentation-only here; no Python source was available to verify.
